Os cálculos foram conferidos

O código antigo e o novo rodam lado a lado sobre as mesmas entradas, e os números são comparados. Hoje são 6 suítes e 80 casos, cobrindo os cantos que costumam quebrar numa migração.

Isso não é formalidade. Ao converter a Empreita, os testes pegaram um erro real: a versão nova ignorava o BDI global da obra. O código rodava sem erro e produzia números plausíveis — só menores que os corretos. Sem a comparação, isso apareceria meses depois, numa medição paga a menos.

O que vem agora

As telas gravam os dados como texto, do mesmo jeito que o app atual. O próximo passo é passarem a usar as tabelas do banco, o que abre consulta e relatórios de verdade.

1
Obra como contexto

Hoje existe uma EAP só no sistema inteiro. Cada módulo passa a pertencer a uma obra — a estrutura de abas já está pronta, falta carregarem os dados daquela obra.

2
EAP para as tabelas

O endpoint já devolve exatamente o formato que a tela usa. A troca é de origem de dados, não de estrutura.

3
Pagamentos para as tabelas

Com os pagamentos em tabela, volta a coluna de orçado x realizado na EAP, que existia no app antigo.

4
Mapa e Empreita para as tabelas

Os maiores, com relações aninhadas — fornecedores, itens, preços e medições.

5
Relatórios

Com os dados em tabelas, dá para comparar obras entre si e ver evolução no tempo — impossível com o formato atual.

Feito: EAP conectada na API de verdade

A EAP deixou de usar a "ponte" genérica de texto e passou a falar direto com o endpoint relacional (GET/PUT /obras/{id}/eap), que já existia pronto no backend. Mapa, Empreita e Pagamentos continuam na ponte por enquanto — só migram quando os endpoints deles estiverem confirmados prontos pro formato que essas telas usam.

Ainda não testei isso contra o banco de dados de verdade — esse ambiente aqui não tem Docker. Recomendo abrir o INICIAR-COM-BACKEND.bat, editar uma EAP, recarregar a página e confirmar que os dados vieram do banco antes de usar pra valer.

Feito: Relatórios movido pra dentro da obra

O relatório de Orçado x Realizado nunca fez sentido como página "geral" — ele sempre compara a EAP com os Pagamentos de uma obra. Agora mora em /obras/{id}/relatorios, igual as outras abas, e não em uma rota solta que lia dados de uma chave antiga (órfã, sempre vazia).

Como consequência dessa limpeza, alguns links que apontavam pras telas de Mapa/Empreita/Pagamentos antigas (removidas na mudança anterior) também foram corrigidos — agora levam para a lista de obras, já que criar qualquer um desses sempre exige escolher a obra primeiro.

Feito: Orçado x Realizado na EAP

Baseado num protótipo mais amplo que você mandou (obracontrol.html): quando a EAP está confirmada, cada item ganha colunas de Orçado e Realizado. O Realizado soma os pagamentos já vinculados àquele item (usando o mesmo campo que já existia no formulário de Pagamentos) e é clicável — abre a lista de pagamentos que compõem aquele total.

Pontos em aberto pra decidirmos juntos: se o Orçado deveria "congelar" no momento da confirmação em vez de recalcular sempre que algo muda depois; se o nível da EAP deveria ser escolhido direto (1 a 4) como no seu protótipo, em vez de inferido a partir do agrupamento; e uma ação de apagar só os valores unitários, separada de apagar tudo.

Feito: obra como contexto

Até 27/07/2026, EAP, Mapa, Empreita e Pagamentos eram globais: existia uma EAP só no sistema inteiro, não importava qual obra estivesse aberta.

Implementado (28/07/2026): cada aba da obra agora carrega e grava só os dados daquela obra. As rotas de editor único sem obra (/mapa, /empreita, /pagamentos na raiz) foram removidas — só existem dentro da obra agora (/obras/{id}/mapas etc.). Ainda é a mesma ponte de texto (não os endpoints relacionais — ver tabela acima), só que separada por obra em vez de um registro único.

Feito: lançamento do contrato por categoria (task #45)

O EmpreitaController já aceitava contrato separado por categoria de custo (contratoEmpPorTipo). Até 27/07/2026 a tela trabalhava com um valor único de empreita e um de reserva, distribuídos automaticamente pela proporção do orçado.

Decisão e implementação (28/07/2026): o lançamento por categoria agora é digitado pelo usuário — a tela da Empreita tem um campo de Contrato e um de Reserva por categoria de custo (mesma lista da EAP), no lugar do campo único de antes. O sistema não distribui mais esse valor automaticamente. O orçado da EAP continua aparecendo como referência, no painel "Contrato x orçado".
