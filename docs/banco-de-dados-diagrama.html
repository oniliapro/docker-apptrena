Multiempresa Obra / EAP Mapa (cotação) Empreita Pagamentos / Diário Chave-valor (não relacional)

app_storage é uma ponte chave→valor (JSON) herdada do app antigo (vanilla), ainda em uso por quatro cadastros simples que nunca foram migrados pra tabela própria: Clientes, Responsáveis, Empreiteiros e Fornecedores — chaves como controleObra.fornecedores.v1, com empresa_id na chave primária composta pra isolar cada empresa. Todo o resto do sistema (Obra, EAP, Mapa, Empreita, Pagamentos, Diário de Obra) já é relacional de verdade, com foreign keys reais no banco.

Isolamento multiempresa: empresas.id é a raiz de tudo — users, app_storage, obras, mapas, empreitas e pagamentos carregam empresa_id diretamente (não só via join com obras), porque mapas/empreitas/pagamentos podem existir sem obra vinculada ainda.

tipos_custo é uma tabela de referência fixa (Material, Mão de obra, Equipamento, Outros, Administração) usada como chave estrangeira em quase todo lançamento de valor por categoria — por isso aparece conectada a tantas tabelas diferentes.

Padrão "detalhe por categoria": várias tabelas (obra_bdi_tipo, eap_item_custos, empreita_tipos_incluidos, empreita_item_contrato_tipo, empreita_item_medicoes_tipo, empreita_registro_linha_tipos) repetem a mesma ideia: chave composta (id do registro pai + tipo_custo_id) guardando um valor por categoria de custo.
